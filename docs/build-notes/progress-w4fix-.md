## DONE (all 7 items). Design notes and limits
1. Break-glass (I7/8.5): migration 0019 `stop_policy_snapshot` (people+role grants, matrix, policies, catalogue roles/actions, project/repo names). Refreshed after every successful policy load (core/decide.ts policyState, core/command.ts post-commit; in-memory digest so unchanged state costs no write). `command()` with `reduced` (stopCommand) loads policy in a savepoint; on failure it decides from the snapshot (core/stop-snapshot.ts), live active stops still read from `stops`. The decision rule becomes I7-SNAPSHOT, the event `after.policyFallback {snapshotAt, cause}` and the response `policyFallback: true`. resolveTarget falls back to the snapshot for projects/repos. Limits: snapshot is as old as the last successful load (a role revoked since stays effective for stops only while policy tables are down; every such use is recorded with the snapshot time); freezes and flow data are not in it; no snapshot yet (fresh install, first load fails) = normal failure; a work-order kill needs a one-row read of work_orders (target lookup, 503 with a hint to kill the project instead); idempotency_keys and events must still work.
2. Halt grace (4.5): reconcileStop for a halt stamps `haltGraceUntil` on live attempts that have a started run and returns `enforcing` with `retryAt` (not marked enforced, nothing revoked). Edge already refuses model calls under any stop and accepts heartbeat/checkpoint/result under a halt (guardRun progress mode). Worker stop.enforce re-enqueues itself at retryAt; then attempts are cancelled, tokens revoked, containers stopped. Grace: WORKER_HALT_GRACE_MS (default 20000; 0 = immediate). Kill is unchanged (immediate). Runner wrapper unchanged (it already checkpoints at turn boundaries and posts its result).
3. Idempotency-Key: command() refuses (422) a create with `idempotent: true` from an API key without the header. Browser sessions already send it (client.ts create option).
4. Run-scoped internal endpoints, egress report/system list and vendor-key read are edge-only (areas/internal/edge-only.ts, plugin preHandler); other service principals get 403 and an audited `internal.edge.denied` / `vendor.key.read.denied` event.
5. Edge proxy: CONNECT tunnels are tracked per run and re-checked against /egress every EDGE tunnelCheckMs (3 s); a refusal cuts all of the run's tunnels; unreachable API cuts after 3 failed rounds. metrics.cut counts cut tunnels.
