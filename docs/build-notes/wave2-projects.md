## Public interface
API routes (services/api/src/routes/projects.ts, export projectRoutes):
- GET /api/v1/projects and GET /api/v1/projects/{id}: legacy Project shape plus `version` and `metrics`. Metrics are computed from tables and are never invented: wip, bays, gates, oldest, late, eff/effN, cov, bad, haltedRepos, byPosition{station|bay:{n,blocked}}, byClass, byGate, slotsUsed, onboarding, health{id,label,icon,detail}. Only visible projects are returned (404 for others).
- POST /api/v1/projects (project.create, idempotent). Body {name,key?,templateId,owner?,teams,desc?,budget?,approvers?,notifications?}. Returns {project, custom:{done,failed}}. It builds flow v1 from the template and applies the template's custom entries. It writes approver rule v1, notification routes, budget, the owner's project_admin grant (unless a factory admin) and project_members. A derived key that is already taken is numbered (PAY2); a key the caller typed that is taken gets 409.
- GET /api/v1/project-presets: {approvers:{standard|light|strict:{gate:rule}}, routes:{...}} for the wizard preview. This endpoint is not in the spec table; I added it.
- GET/POST /api/v1/templates, PATCH /api/v1/templates/{id}. POST takes {fromTemplate|fromProject,name?} (template.edit, idempotent). PATCH takes the partial template and If-Match on template version; built-in templates are refused with 409.
- GET/POST /api/v1/saved-views, PATCH/DELETE /api/v1/saved-views/{id}. Per person (action null); views are {id,name,screen,project,s,version}; name unique per person and screen; PATCH and DELETE take If-Match.
- PATCH /api/v1/projects/{id}/config, If-Match on project version. Body is {gate,mode} or {path,value}. Paths: desc, overlay, owner, mcp, notifications (notify.edit), budget.monthly, budget.alertAt, flow.slots, flow.classes, flow.stations.{id}.enabled|wip, flow.gates.{id}.enabled. Flow edits publish a new flow_versions row and bump gate_modes.
- POST /api/v1/projects/{id}/flow/{stations|gates|bays|classes} (idempotent), DELETE /flow/stations/{id}, PATCH /flow/stations/{id} {move:-1|1}, PATCH /flow/classes/{id}. All take If-Match on project version.
- PUT /api/v1/projects/{id}/approvers/{gate} {value:rule}: validated (roles, people, N vs eligible members, conditions), publishes approver_rule_versions.
- PUT and DELETE /api/v1/projects/{id}/members/{person}/roles/{role}: project-level roles only; If-Match is the person version.
- POST /api/v1/projects/{id}/archive {confirmText}, POST /unarchive: If-Match on project version.
Spec 15.4 on every command: decision point plus <action>.denied audit; state and event in one transaction; archived and killed projects refuse config with the reason; approvers and members refuse only when archived.
Not mine: PUT /people/{id}/away (the Approvers tab calls it; the people engineer already built it).
Web: default exports views/projects.tsx and views/project-config.tsx. Exported from views/projects/portfolio.tsx: Portfolio {ctx, projects, defaultLayout, roles?} and ProjectCard. Exported from views/projects/kit.tsx: MiniBelt, GateDiamond, ClassChip, HealthChip, RouteMatrix, DataTable, useCatalog, useTeams, goProject, evName. ops.ts: updateSavedView and deleteSavedView now take Versioned; addStation, addGate, addBay and addClass now send Idempotency-Key.
