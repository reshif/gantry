# Wave 4: models, vendors, routing, prices and budgets

## Summary
The Models area is real end to end: vendors (hosted and custom), models, versioned routing, price versions with effective dates, and cost caps at project and work-order scope, all through `command()`. The model gateway's authorize step now uses the same resolver as `GET /routing/resolve`, so the preview on the screen cannot disagree with what a run gets. Cross-model fallback is off in a new install. The Models screen is ported from `legacy/js/views/models.js` against the real API. Real vendor calls are unverified (no keys).

## Public interface
Endpoints (services/api/src/routes/models.ts, logic in areas/models/):
- Reads (signed-in people): `GET /api/v1/vendors` (legacy `Vendor` shape plus `retention`, `custom`, `qualified`, `version`; health, latency p50 and spend MTD come from `usage_meter`, never from a stored claim; prices are the version in force), `GET /api/v1/routing` (legacy `Routing` plus `classOverrides`, `projects`, `crossModelFallback`, `version`), `GET /api/v1/routing/resolve?station=&repo=&project=&class=&model=` (`{model, vendor, wanted, layer, steps[], rule, blocked, alternates[], crossModel, sameModelFallback}`), `GET /api/v1/prices` (`{current, versions[]}`), `GET /api/v1/prices/quote?model=&at=&input=&output=&cacheRead=&cacheWrite=` (cost at the version in force at `at`), `GET /api/v1/budgets` (per visible project: monthly, alertAt, perWorkOrder, spent MTD, version).
- Commands (action `model.edit`, factory scope, refused while the factory is killed, denials audited): `POST /vendors` (idempotent; custom vendor: https base URL, key sealed with the data key under AAD `vendor:<id>`, marked custom and not qualified), `PATCH /vendors/{id}` `{patch:{connected,key,region,endpoint,product,budget,residency,retention}}` (optional `If-Match` = vendor version), `POST /vendors/{id}/qualify {station}` (needs a completed eval run on that vendor, `eval_runs.data.vendor`, at or above the station suite's threshold), `POST /models` (idempotent, also publishes a price version), `DELETE /models/{id}`, `PATCH /models/{id} {enabled}`, `PUT /routing {routing, label}` (If-Match required: the routing version), `POST /prices {prices, effectiveFrom?, note?}` (idempotent; effective now or later, never in the past).
- `PUT /api/v1/budgets/{project} {perWorkOrder}` (action `project.config` in the project): the default per-work-order cap in USD, 0 = none. The monthly budget stays in project config (existing `budget.monthly`).
- Internal (edge): `POST /internal/v1/runs/{id}/authorize` returns `route: {vendor, baseUrl, modelId, upstreamModel, crossModel?, keyless?, alternates?: [{vendor, baseUrl, modelId, upstreamModel, crossModel, keyless?}]}`. `POST .../usage` accepts `fallback: same_model|cross_model` and `wanted`; it flags the run (`runs.data.fallbacks`) and writes a `model.fallback` event (a cross-model one is outcome `regression`).
- Exports: `areas/models/resolve.ts` (`resolveModel`, pure), `facts.ts` (`resolveFor`, `loadFacts`), `prices.ts` (`priceBookAt`, `costMicros`, `publishPriceVersion`, `listPriceVersions`).

Routing body (routing_versions.body): the legacy `{defaultModel, overrides (station -> model), fallback[], rules[]}` plus `classOverrides` (class -> model), `projects` (`{defaultModel, overrides, classOverrides, allowedVendors, allowedRegions, allowedRetention, crossModelFallback}` per project) and `crossModelFallback` (the factory switch). Every save is a new immutable published version; `If-Match` is the version number.

## Behaviour (spec 10.4, 10.5)
- Resolution order: default, then project, then station, then class (each narrower layer replaces the one before; within station and class, the project's own entry beats the factory's). An agent's pinned model replaces the routed choice but not the filter.
- Filter before any fallback: the project's allowed vendors (routing policy and the older `projects.config.extra.allowedVendors`), allowed regions (substring match on the vendor's region), allowed data-retention modes (`vendors.config.retention`: `zero`, `30d`, `standard`), the repo's residency rule (tags, plus `regulated` for a regulated project; `rule.use` with its region, or `rule.alt`), model enabled, vendor connected, and for a custom vendor: the station must be qualified.
- Fallback: automatic only to the same model on another allowed vendor. "Same model" = same `canonical` id (`models.data.canonical`, default: the id with a vendor prefix such as `bedrock-` removed). A different model needs both the factory switch (`routing.crossModelFallback`, off) and the project's opt-in (`projects[pid].crossModelFallback` or `projects.config.extra.crossModelFallback`); the run is flagged. With no allowed vendor, authorize refuses (`code: route`) and the preview shows "Blocked", it never leaves the residency.
- Edge (services/edge/src/gateway.ts): the route's alternates are tried in order only when the vendor failed before any byte reached the run (connection error, 429, 5xx, 529), each with its own key and limiter slot. The request's `model` is rewritten to the vendor's own id when it differs (`upstreamModel`). An endpoint vendor with no stored key (on-prem without a token) is `keyless`: no key header is sent. Usage is reported with the vendor and model actually used, plus `fallback` and `wanted`. Metric `fallbacks`.
- Prices: `price_versions.effective_from` (nullable, null = published_at). The price in force at a moment is the published version with the latest effective date not after it (ties: higher version). The usage endpoint prices each call at the version in force when it is recorded and stores that version on the row. `GET /prices/quote?at=` prices a usage at any moment. Backdating is refused.
- Budgets: `loadLimits` (areas/internal/metering.ts) now reads the project monthly cap and the new `budgets.wo_limit_micros` (per-work-order default), with a work order's own `data.budgetUsd` taking precedence and `config.extra.woBudgetUsd` as the last fallback. Breach behaviour is unchanged (next call refused, work order halted with cause `budget` at the turn boundary).
- Disconnecting a vendor removes its sealed key. A vendor on which the factory default sits cannot be disconnected; a model that routing or an agent uses cannot be removed or (primary) disabled.

## Screen (apps/web/src/views/models.tsx and models/*)
Ported faithfully from legacy models.js: same classes and ids (`vendor-<id>`, `vendor-connect-<id>`, `mt-<model>`, `md-rm-<model>`, `rt-default`, `rt-st-<station>`, `rt-fb-up|down|rm-<i>`, `rt-fb-add`, `rr-*`, `rt-prev-*`, dialog ids `vc-*`, `vd-submit`, `va-*`, `ma-*`), disabled-with-reason through `useCan("model.edit")`, same texts except where they described the simulation. Routing edits send the whole object with `If-Match` = the loaded routing version. The route preview asks the API.
New, because the spec asks for them: per-vendor data retention (connect and add dialogs), station qualification for a custom vendor (chips, station picker, "Record qualification"), per-class overrides, the factory switch "Different-model fallback" (`rt-cross`, off), the per-project policy block (`rt-proj*`: default model, allowed vendors, regions, retention, cross-model opt-in locked until the factory switch is on), "Same model as" in the add-model dialog, the Price versions panel (`pv-*`, effective-from date, scheduled and in-force chips) and the Work-order budgets panel (`bd-*`).
Dropped, on purpose: the "Test connection" button and its simulated answer (health and latency come from the metering of real calls; there is nothing to simulate), the "simulated" wording in the connect and add-vendor dialogs, and the client-side route resolver.
Shared files touched (minimal): `packages/domain/src/types.ts` (optional fields on `Model`, `Vendor`, `Routing`; new `ProjectRouting`), `apps/web/src/api/{ops,queries,keys}.ts` (`qualifyVendor`, `publishPrices`, `setWoBudget`, `usePrices`, `useBudgets`, richer `useRoutingResolve`), `apps/web/src/styles/views.css` (one block), `services/api/src/areas/internal/{route,metering,runs}.ts`, `services/edge/src/{gateway,api}.ts`.

## Unverified
- Real vendor calls: no keys. The edge fallback, key injection, `upstreamModel` rewriting and the Bedrock/OpenAI-style endpoints are tested against a fake vendor only. The gateway speaks the Anthropic messages API; an OpenAI-style custom vendor or Bedrock's own signing is not translated (a vendor must expose that API).
- The Bedrock vendor has no endpoint in the seed, so a route to it is refused ("has no endpoint") until one is set; the edge does not do AWS signing.
- Qualification trusts `eval_runs.data.vendor` set by the evals area; no code writes that field yet (the evals engine is another area).
- Health is derived from the last hour of metered calls (degraded at 5 or more calls and an error rate of 2% or more); there is no active probe.
- Multi-replica behaviour of the routing and price advisory locks was not exercised.
- Monthly vendor invoice reconciliation (spec 10.4: the difference stored monthly) is not built.
- The Models screen for a person without `model.edit` is blocked by the shell's route guard in the live run; the read-only rendering is covered by the web test only.
