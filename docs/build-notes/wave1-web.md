# Wave 1: web

## Summary
Built the React shell for @gantry/web in apps/web. It has Vite, React 19 and strict TS, the legacy CSS copied unchanged, a typed API layer, the ported app shell and sign-in screen, 24 placeholder views, and the Dockerfile with nginx.conf. Typecheck, vite build and 50 vitest tests pass. The image `gantry-web:dev` builds and passes a `--read-only --tmpfs /tmp --user 10001:10001` run: `/healthz` and `/` return 200 and the healthcheck is healthy. Playwright screenshots of the sign-in screen and the shell match legacy closely. Nothing was tested against a real API, since none exists yet. The responses to `/api/v1/me`, `/home` and the rest are mocked in the screenshots and tests, and several API paths and ids are my choices (listed under notes_for_integration).

## Public interface
API client (src/api/client.ts):
- `command<T>(path, {method, body, query, idempotent, ifMatch, headers, signal}) -> Promise<ApiResult<T>>` never rejects on expected outcomes. Result is `{ok:true,msg,status,...extra}` or `{ok:false,msg,status,rule?,needs?}`.
- `get<T>(path, query?)` throws `ApiError{status,body}`. Also exported: `getText`, `streamCommand`, the verbs `post`/`put`/`patch`/`del`, `api(path)`, `setCsrfToken`, `setUnauthorizedHandler`.
- A missing CSRF token is fetched from `/me` before the first state-changing request.

Ops (src/api/ops.ts):
- `ops` has one function per legacy G.ops operation. It also exports `loginUrl(method, hint?)` and `ops.signIn`, which navigates the browser.
- Result shape is `Promise<ApiResult>`. Examples: `ops.submitWO(o, via?)`, `ops.approveGate(woId, gateId, via?, {ifMatch}?)`, `ops.kill(scope, id, {reason, mode, confirmText}, via?)`, `ops.restore(scope, id, reason, via?)`, `ops.setProject(projectId, path, value)`.
- Not included, by design: `recordSignInFailure`, `simulateChecksPass`, `recordOutcome`, `change`, agent-side `raiseQuestion`, `setReplay`, `openRecord`. `setReplay` and `openRecord` are in lib/prefs.ts.
- Each ops function invalidates its slices through `invalidateSlices`.

Queries (src/api/queries.ts):
- Hooks: `useMeState`/`useMe`, `useSessions`, `useSecurity`, `useSignins`, `useHome`, `useActivity`, `useProjects`, `useProject`, `useSavedViews`, `useTemplates`, `useFloor(projectId, at?)`, `useProjectEvents`, `useWorkOrders`, `useWorkOrder`, `useConversations`, `useRecord`, `useRecordMarkdown`, `useChanges`, `useKillImpact`, `useRepos`, `useGuidelines`, `useAgents`, `useAgentEffective`, `useInstructions`, `useSkills`, `useVendors`, `useRouting`, `useRoutingResolve`, `useScorecards`, `useSuiteRuns`, `useEvalsFactory`, `useTrustCells`, `useLearningFindings`, `useLearningProposals`, `useIntegrationTypes`, `useIntegrations`, `useRoutes`, `useDeliveries`, `useCardTemplates`, `useMcpServers`, `useMcpAccessCheck`, `useMcpCalls`, `useApiKeys`, `useApiConfig`, `useApiRequests`, `useTriggers`, `useTriggerRuns`, `usePeople`, `useEffectivePermissions`, `useAccessMatrix`, `usePolicies`, `useFreezes`, `useAudit(filters)`, `useAuditEntry`, `useAuditVerify`, `useWorkload`.
- Also exported: `useNavBadges`, `fetchMe`, `recordExportUrl`.
- Keys are built by `qk.*` in src/api/keys.ts, and every key's first element is the legacy slice name.

Other API modules:
- `startStream(opts?) -> stop` in src/api/stream.ts. It also exports `parseChange` and `backoffDelay`.
- `useCan(action, {project, repo, time}) -> {allowed, reason, needs, rule?, pending}`, `useCanMany`, `canBatcher` and `CanBatcher` in src/api/can.ts.
- `invalidateSlices(slices)` and `expandSlices` in src/api/keys.ts.

Shell and UI (src/lib, src/ui):
- Router: `useHash()`, `navigate(id, param?)`, `parseHash`, `formatHash`.
- Prefs and routes: `usePrefs`/`updatePrefs`/`setProject`/`openRecord`/`setReplay`, `ROUTES`/`canSeeRoute`/`resolveRoute`/`pickProject`, `registerCommand(id, fn)`.
- UI primitives: `Icon`, `Logo`, `Btn`, `IconBtn`, `Toggle`, `Select`, `Field`, `LockNote`, `Tabs`, `Segmented`, `StateChip`, `Chip`, `Mono`, `Avatar`, `Who`, `Empty`, `ViewHead`, `Panel`, `Meter`, `Table`, `useCopy`, `useFieldId`.
- Charts: `Spark`, `AreaChart`, `BarChart`.
- Overlays: `useUI()` gives `toast`, `dialog`, `open`, `confirm`, `reasonDialog`, `typedConfirm`, `drawer.{open,close,isOpen}`, `popover`, `menu`, `closeTopDialog`, `closeAllDialogs`. The `Dialog` component is also exported.

Views:
- `src/views/<id>.tsx` has a default export per route.
- `src/views/traveler.tsx` is the drawer placeholder, opened through `useOpenTraveler()` in shell/useTraveler.tsx.
- Views are lazy-loaded through src/views/index.ts.

## Unverified
- Nothing was tested against a real API; all of `/api/v1/*` was mocked, so every response shape is untested. That covers `me`, `home`, floor and the others, plus ops paths and the SSE stream. The EventSource was exercised only with a fake in unit tests, and a real SSE connection was never opened.
- `/auth/login` and `/auth/logout` were exercised only against mocks (redirect and POST).
- Not verified: any behaviour of the 24 placeholder screens beyond rendering the placeholder.
- Not run: `docker compose`, the Caddy ingress and the 10001 user together with the compose healthcheck.
- Not verified: window sizes below 1440x900, mobile nav-open behaviour, rail mode visuals, light/dark theme switching visually, and keyboard focus trapping beyond the jsdom tests.
- `npm ci` in the Docker build needed `--ignore-scripts` and the optional cacert BuildKit secret in this proxy environment, same as the launcher Dockerfile. A build without the secret was not tried after that fix, so a plain-network build is untested here.
- The nginx-unprivileged image was pulled after Docker Hub rate-limited (429) the first attempts. The Dockerfile pins `nginxinc/nginx-unprivileged:1.27-alpine`.
