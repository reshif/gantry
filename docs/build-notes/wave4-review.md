# Wave 4 review

## Fixed
- Security (spec 12.4): runners could reach MCP servers directly through the edge proxy, which skipped the gateway's scope, definition-hash and write pre-authorisation checks. runEgressHosts listed the hosts of in-scope MCP servers, so for a server with auth mode 'none' a run could call write tools with no grant and no log entry. A run's egress allow-list no longer contains any MCP host, so the gateway at /mcp/v1 is the only way to reach a server. Files: services/api/src/areas/internal/egress.ts and services/api/src/areas/internal/runs.ts. services/api/test/internal-runs.test.ts now asserts the MCP host is absent, and the remaining-items line in docs/build-notes/wave4-mcp.md is updated.
- Promotion gate bypass (spec 13.2): eligibility() in services/api/src/areas/agents/store.ts matched eval runs by version label only, and labels default to '<n>.0.0', so two agents can share a label. When two agents share a suite (suites.agent_id null), a passing run of another agent's version with the same label unblocked promotion. Runs found by label must now also carry the same data.agent. Test added in services/api/test/agents.test.ts: a passing run for ag-review labelled 2.8.0-rc1 does not count. It fails without the fix (200 instead of 403) and passes with it.
- Spec 12.5, keys expire: the API accepted expiresInDays: null and created a key that never expires. The schema no longer accepts null, and every key gets an expiry, 90 days by default (services/api/src/areas/apikeys/schemas.ts and commands.ts). The web UI never sent null. Test: services/api/test/apikeys.test.ts, where null now returns 422 and the default is about 90 days.
- The chat-link one-time code was kept in plain text in the stored idempotent reply (idempotency_keys.response) and in msg. The route now uses storedOmit ['code','command'], and msg no longer contains the code (services/api/src/areas/integrations/links.ts). services/api/test/notify.test.ts asserts the code is absent from idempotency_keys and from the event.
- Fidelity: the shared Empty primitive dropped the legacy G.emptyState id. It now takes an optional id (apps/web/src/ui/primitives.tsx, a small change to a shared file). The legacy ids are restored on the new screens: ag-trust-none and ag-trust-empty (agents/Trust.tsx), int-cat-empty (integrations/Tabs.tsx), sk-empty (skills.tsx), tr-matrix-empty (trust/Ladder.tsx) and onb-empty (onboarding/Pipeline.tsx).
- Flaky test: services/api/test/stream.test.ts failed about 1 run in 3, because the two SSE streams receive the same NOTIFY independently and the test assumed the admin's copy arrived first. It now waits for both copies. Six repeat runs passed.

## Remaining
- Learning loop: an accepted 'eval' proposal adds a case to a suite. That is allowed by spec 13.4, but an easy case raises a suite's mean score and could help a candidate clear the promotion threshold. A person must accept it (two-person rule), but there is no check that a new case does not lower the bar. A 'route' proposal may add a skip for a station whose only gate is automatic (for example research, G1f), which drops an automatic check.
- In-chat approval (12.3): the Slack connection's own project scope is not checked against the gate's project. Any linked, permitted person can approve a named gate in any project from any switched-on Slack connection. The decision point still applies. The admin-named gate list can include G5 (review and merge). Only G6, G3G3s, hotfix, security hold and risk-tagged changes are hard-blocked. A malformed interactive 'payload' JSON returns 500 after the signature is verified. Teams has no delivery or interaction path; it is listed as unavailable.
- API keys keep working after the person who created them loses their own rights. decideApiKey checks only the key's scopes, project and stops. Expiry (now always set) and revocation are the only limits.
- MCP: mcp-authorize checks the definition hash only when the edge sends one (definitionHash is optional in the body). The edge sends it when the tool appears in the upstream listing. The API does not check it when the listing lacks the tool. Calls left 'allowed' when the edge dies stay 'running'. No engine step issues write grants yet: an approver uses POST /mcp/grants by hand.
- Runner egress still includes vendor endpoints and ANTHROPIC_BASE_URL (wave 3 design). The runner only needs the edge, and it holds no keys (I2 holds), so this is defence in depth only.
- Spec 15.4 coverage: every new state-changing route goes through command() or stopCommand(). The exceptions are read-only POSTs (simulate, preview, can, console tools and explain, card preview) and the signed hooks (/hooks/slack, /hooks/trigger), which write their own audited denials. The trust switch, learning switch and console send have no If-Match (toggles and appends). services/api/test/workload.test.ts has no denied or stale cases because workload is read-only. There is no skills-specific test file; skills are covered inside agents.test.ts.
- Fidelity gaps in the ported screens, all documented by the builders and mostly simulation-only: Models 'Test connection' (vendor-test-*) dropped; Learning 'Draft with Claude' (ln-d-ask, ln-d-stop) dropped; Trust 'Simulate incident' (tr-sim-incident, tr-inc-*) replaced by a real outcome dialog; Onboarding 'Simulate checks pass', 'Resume simulation' and the onb-to-int link callout dropped; Console local classifier card (con-cls*, con-route, con-step*), kill-impact block (con-impact) and repo suggestion chips (con-repo-*) dropped, and con-cf-onb-* is renamed con-onb-open-*; Notifications paging preview (np-page*) not rendered. Empty-state ids on screens from earlier waves are still not set; Empty now accepts one.
- Not run by me: the full compose stack, Playwright screenshot comparison against legacy/index.html, and any real GitHub, Slack, vendor or MCP server. I compared screens structurally, checking the legacy ids and classes against the React sources. The w4e2e walk covered live rendering. T11 and multi-replica remain unverified, as in the E2E report.
- Not changed: wave 3 remaining items carry over (the stop path still reads policy data; halt versus checkpoint; CONNECT tunnels are not cut when a stop lands; symlink and submodule entries pass through the broker).
