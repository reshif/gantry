# Wave 4: MCP (spec 8.8 MCP row, 12.4, 6.4 MCP gateway)

## What exists

**Registry (API).** `services/api/src/areas/mcp/` and `routes/mcp.ts`.
- Migration `0022_mcp_registry.sql`: transport (`http` | `sse`), protocol revision, auth mode (`none` | `bearer` | `header`), auth header, sensitivity, health, discovery time on `mcp_servers`; `description`-free tool rows keep the definition in `definition jsonb`, the server's class hint in `hint`, and `pending_hash` (a rediscovery or a call found a different definition); `classes` on `mcp_scopes`, one scope row per server.
- Endpoints: `GET /api/v1/mcp/servers`, `GET /mcp/servers/{id}`, `POST /mcp/discover` (audited, saves nothing), `POST /mcp/servers`, `PATCH|DELETE /mcp/servers/{id}` (`If-Match` = server version), `POST /mcp/servers/{id}/discover` (check again), `POST /mcp/servers/{id}/approve` (re-approve changed definitions), `POST /mcp/grants` (pre-authorise write tools for a work order's live attempt; action `gate.approve` in the work order's project), `GET /mcp/access-check`, `GET /mcp/calls`.
- Every write goes through `command()` with action `mcp.edit`: denial audited, factory kill refuses with the stop reason, creates take `Idempotency-Key`, PATCH/DELETE/discover/approve take `If-Match`. Events: `mcp.add`, `mcp.edit`, `mcp.remove`, `mcp.discover`, `mcp.approve`, `mcp.server.disabled`, `mcp.grant`, `mcp.call` (writes and failures), `mcp.call.denied`. No event or response carries a secret, only its mask.
- Tool definitions and hashes always come from a discovery the edge made. The browser only sends the admin's choices (class, allow) by tool name. The admin-set class wins; the server's `readOnlyHint` is stored as `hint` and shown as "server suggests". A tool without `readOnlyHint: true` is suggested as write.
- Credentials: sealed with the data key, AAD `mcp:<id>`, shown as `secret_mask` only.
- A changed definition (found on rediscovery, or by the gateway at call time) sets `pending_hash`, disables the server with `disabled_reason`, and refuses calls until an admin re-approves. Approve rediscovers and accepts what the server reports now; it refuses (409) if a tool changed again since the flagged hash. Changing the address or transport disables the server the same way. `PATCH enabled:true` is refused while a reason is set. Removing a server also removes it from every project's enabled list.
- Scope: `areas/mcp/scope.ts` is the single resolver used by the run spec, the gateway authorisation and the access check: project, the project's own enable list (Project config), repo, agent, station, work class. `mcpServersInScope` (areas/internal/spec.ts) now applies project config and class; the run spec names a server `docs-wiki` style (legal harness names, `mcpKey`).

**Internal API for the edge** (`areas/mcp/internal.ts`, edge service token plus a live run token): `POST /internal/v1/runs/{id}/mcp-tools` (allowed tools; a write tool only if the attempt holds its grant), `mcp-connection` (url, transport, sealed credential opened, `Cache-Control: no-store`, only for an in-scope server of a live run), `mcp-result` (completes the call row: outcome ok|error, latency, error text; writes and failures also go to the ledger). `mcp-authorize` (areas/internal/runs.ts) now returns `callId` and records `pending_hash` when it disables a server.

**Edge gateway** (`services/edge/src/mcp/`).
- Toward the runner: a stateless MCP server at `/mcp/v1/{serverId}` (JSON answers; `initialize`, `ping`, `tools/list`, `tools/call`; anything else is -32601). The run token is the bearer. `tools/list` comes from the registry (API), never from the real server.
- `tools/call`: connection from API, look at the tool's current upstream definition (hash), `mcp-authorize` (scope, allow, class, write pre-authorisation, definition hash; logged with an argument hash whatever the answer), call upstream with the credential injected (bearer or named header), `mcp-result`. Refusals come back as a tool error (`isError`) so the model reads the reason. Read calls retry up to 2 times on network errors, timeouts, 429 and 5xx; **write calls are sent once**. The edge fails closed (503) when the API cannot be reached.
- Toward the server: own small client (`upstream.ts`) for streamable HTTP (JSON or SSE answers) and the older HTTP+SSE transport; all sockets go through one undici agent whose DNS lookup rejects private addresses (and literal private IPs are refused up front), `redirect: error`, the credential never leaves the process and is redacted from error text. The message endpoint of an SSE server must stay on the registered origin.
- `POST /mcp-admin/v1/discover` (edge service token): connects, lists tools (paged), returns hashes and hints. The API calls it through `areas/mcp/edge-client.ts` (`EDGE_URL`).
- Definition hash: sha256 of canonical JSON of name, title, description, input and output schema, annotations (`definition.ts`).

**Screen.** `apps/web/src/views/mcp.tsx` and `views/mcp/{kit,AddDialog,Detail,Usage}.tsx`, ported from legacy `views/mcp.js` with the same classes and ids (`mcp-add`, `mcp-row-*`, `mcp-open-*`, `mcp-sens`, `mcp-writegate`, `mcp-tool-*`, `mcp-sc-*`, `mcp-chk-*`, `mcp-f-*`, `mcp-more`, `mcp-remove`, `mcp-remove-go`). Added: class select per tool (admin sets read/write, server hint shown), Enabled switch, Check again, disabled note with Review and re-approve, protocol revision and last discovery, "changed" chip. Access check and usage log come from the API.

Dropped from the legacy screen, on purpose: stdio servers (run on the runner, outside the registry); OAuth, mTLS and Vault role auth (the edge injects a bearer token or an API key header; the others are not implemented); the write-gate switch (write tools always need the pre-authorisation, so it is shown on and locked with the reason); the "gated" outcome and filter (a write call without its pre-authorisation is denied; the usage log has "running" for an authorised call that has not reported yet); every "simulated" label.

## Operating notes
- `GANTRY_MCP_ALLOW_HTTP=true` lets the registry accept `http://` server URLs (trusted networks only). Default: https only. Not set in `deploy/compose.yml`.
- The edge needs no new config. `mcpTimeoutMs` (optional, default 30 s) bounds one upstream call. The edge's `blockPrivateAddresses` guard applies to MCP servers too: a server on a private address is refused unless that guard is off (it is off only in tests).
- The usage log reads the newest 500 calls (`GET /mcp/calls?limit=`, `before=<id>` pages back).

## Remaining and caveats
- `GET /api/v1/agents` returned 404 in the live run (another area), so the Agents scope and the access check's agent list were empty there; the unit tests cover them and the API test covers the access check. The screen reads the list as soon as the endpoint exists.
- A call left `allowed` (the edge died between authorize and result) stays "running" in the log. A reaper in the worker could close such rows after the run ends.
- No engine step grants write tools yet: `POST /mcp/grants` is the gate approver's way to pre-authorise the live attempt, and a retried attempt starts with none. Wiring it into the station gate approval UI is left to the flow screens.
- Fixed in the wave 4 review: the runner's egress allow-list no longer includes MCP server hosts (`runEgressHosts`). A run reaches MCP servers only through the gateway, so scope, the definition hash and the write pre-authorisation cannot be skipped by calling a server without its own auth directly through the proxy.
- Upstream sessions are opened per call (initialize, list, call, close). Pooling would cut the round trips.
- Not verified: a real third-party MCP server, OAuth-protected servers, servers behind the real egress network, the Claude CLI as the client (the SDK client was used), and the full compose stack.
