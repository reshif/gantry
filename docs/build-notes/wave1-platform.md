# Wave 1: platform

## Summary
Platform layer built and verified against real Docker, except the MinIO image (not pullable here), the full-toolchain runner build (apt unreachable here) and everything that needs a model key or GitHub. deploy/ has the compose stack for spec section 3, the Caddyfile, a Keycloak realm with all 15 legacy people, an idempotent secrets generator, smoke.sh and READMEs. services/launcher is a Fastify service on :9100 with a fixed runner template and a 37-test suite. runner/ has the gantry-runner image and a TypeScript wrapper with a `stub` adapter and a `claude` adapter.

In a partial stack (postgres, migrate, keycloak, mailpit, caddy, launcher, plus stand-ins for web, api and edge) smoke.sh passed 42 of 42. A real start-run drove the real runner image through the stand-in edge: it fetched the spec, heartbeated, checkpointed and posted a result with the stub adapter. Keycloak imported the realm (run through `mirror.gcr.io/keycloak/keycloak:26.4`, i.e. Keycloak 26.4.7) and a PKCE sign-in returned `gantry_id`, `acr` and `auth_time` for all 15 users.

## Public interface
LAUNCHER (http://gantry-launcher:9100, `Authorization: Bearer <launcher_token>`, reachable from gantry-worker only).
- POST /v1/runs, body `{runId, workspaceRef, variant, runToken, seedComplete?}`. It is a strict zod schema, so any other field gets 422.
  - runId matches `^[A-Za-z0-9][A-Za-z0-9_-]{0,62}$`. variant must be a key of RUNNER_VARIANTS. runToken is the per-run token issued by the API (16-512 URL-safe characters); the launcher only forwards it.
  - Responses: 201 `{ok, runId, state: "prepared"|"started", network, volume, subnet, container?}`; 200 with `state: "running"` if already running; 422 invalid; 409 conflict; 429 capacity or subnet exhausted; 503 `image_missing` or `edge_missing`; 502 docker error.
  - `seedComplete:false` creates `run-<id>` and `ws-<id>` and returns `prepared` without starting a runner. A later call with `seedComplete` true or absent starts it.
- DELETE /v1/runs/:id?keepWorkspace=true|false. The volume is kept unless `false`, so the default is to keep. Returns 200 `{ok, runId, found, container, network, volume, errors[]}`. It is idempotent, and returns 500 `teardown_incomplete` with the partial `stop` outcome if cleanup fails, so retry it.
- GET /v1/runs returns `{ok, runs:[{runId, variant?, workspaceRef?, container|null, network|null (with subnet and attached containers), volume|null}], capacity:{max, networks}}`.
- GET /healthz needs no token and returns 200 when Docker answers.
- Runner template: network `run-<id>` (internal, explicit /28 from RUN_SUBNET_POOL, default 10.213.0.0/16), volume `ws-<id>` at /workspace, container `gantry-runner-<id>`, user 10001:10001, read-only rootfs, CapDrop ALL, no-new-privileges, /tmp tmpfs noexec/nosuid, memory/swap/cpu/pids limits, env exactly `EDGE_URL`, `HTTPS_PROXY`, `GANTRY_RUN_TOKEN`, `GANTRY_RUN_ID`. Labels are `gantry.run`, `gantry.managed-by=gantry-launcher`, `gantry.variant`, `gantry.workspace-ref`. The edge is attached to each run network with alias `gantry-edge`.
- Launcher config env: `RUNNER_VARIANTS` (name=image,...), `RUN_SUBNET_POOL`, `RUN_SUBNET_PREFIX`, `MAX_CONCURRENT_RUNS`, `EDGE_URL`, `RUNNER_PROXY_URL`, `EDGE_COMPOSE_SERVICE`, `EDGE_COMPOSE_PROJECT`, `EDGE_CONTAINER`, `RUNNER_MEMORY_MB`, `RUNNER_CPUS`, `RUNNER_PIDS`, `RUNNER_TMP_MB`, `STOP_GRACE_SECONDS`, `LAUNCHER_TOKEN_FILE`.

EDGE `/run/v1/*` contract expected by the runner wrapper (token is `Authorization: Bearer $GANTRY_RUN_TOKEN`; 401/403/409/410 means the token was refused and the wrapper stops).
- GET /run/v1/spec returns JSON. Required: `adapter` ("claude"|"stub"), `station`. Optional: `model`, `instructions`, `skills[{name,content}]`, `mcpServers{name:{type:"http"|"sse",url}}`, `toolAllowList[]`, `limits{turns,costUsd?,wallClockSeconds}`, `heartbeatSeconds`, `input`, `stub{output?,failWith?,delayMs?}`. Unknown fields are tolerated.
- POST /run/v1/heartbeat `{runId, at, seq, phase, turn?}`.
- POST /run/v1/checkpoint `{runId, at, turn, kind:"transcript"|"artefact", name, contentType, content}`.
- POST /run/v1/result `{runId, at, status:"succeeded"|"failed"|"interrupted", output?, usage[{model,inputTokens,outputTokens,cacheReadTokens?,cacheWriteTokens?,costUsd?}], error?{code,msg}, adapter, capabilities{cancel,resume,mcp,usageDetail}}`.
- On model calls the claude adapter sends `ANTHROPIC_BASE_URL=$EDGE_URL/model` with `ANTHROPIC_AUTH_TOKEN=<run token>`. MCP servers get `Authorization: Bearer <run token>`.
- Wrapper exit codes: 0 delivered, 2 bad env, 70 spec unavailable or invalid, 71 refused by the edge, 72 result undeliverable.

DEPLOY.
- Service names, ports and networks follow spec 3 and docs/BUILD.md. Images are `gantry-{web,api,worker,migrate,launcher,edge,github}:dev`. `gantry-runner` is a build-only service in profile `runner-image`: `docker compose -f deploy/compose.yml build gantry-runner`.
- Commands: `deploy/secrets/generate.sh`, `export DOCKER_GID=$(stat -c %g /var/run/docker.sock)`, `docker compose -f deploy/compose.yml up -d --build`, `deploy/smoke.sh`.
- smoke.sh knobs: `SMOKE_NO_UP`, `SMOKE_SERVICES`, `SMOKE_EXTRA_COMPOSE`, `SMOKE_TIMEOUT`, `COMPOSE_PROJECT_NAME`.
- Ingress: https://localhost (`/healthz` is answered by Caddy itself). Routes are `/api|/auth|/hooks` to the api, `/idp` to keycloak:8081, `/mail` to mailpit, everything else to web.
- Keycloak realm `gantry`, client `gantry-web`, issuer `https://localhost/idp/realms/gantry`, redirect `https://localhost/auth/callback`. Demo users: username is the email prefix (e.g. `asha`), password `gantry-dev`. Claims: `gantry_id` (e.g. `p-asha`), `gantry_title`, `acr`, `auth_time`.

## Integration notes
["Secret file mode: `generate.sh` writes the directory 0700 but files 0644 by default, not 0600 as requested. I tested compose: file secrets keep host ownership and mode (the `uid`/`mode` options are ignored outside Swarm), so a 0600 file owned by the host user is unreadable by uid 10001 or 70 in the containers. The 0700 directory is the real access control. `GANTRY_SECRETS_MODE=0600` restores owner-only for setups where that works. Say if you want a different trade-off, such as chowning to 10001 as root.", "Launcher interface differs from the brief in one way: `start-run` also requires `runToken` (the per-run token issued by the API), because `GANTRY_RUN_TOKEN` has to come from somewhere. It is the only extra field. The worker should call POST /v1/runs, then call gantry-github's seed on volume `ws-<id>`, then call POST /v1/runs again with `seedComplete:true`. The seeder must write as uid and gid 10001, the runner's user.", "stop-run defaults to keeping the volume, so the worker must send `?keepWorkspace=false` after publish. The reaper should call GET /v1/runs and DELETE orphans.", "Env vars I added beyond BUILD.md, which the api, edge and github engineers must read. ## Unverified
- MinIO: neither `quay.io/minio/minio` nor `minio/minio` could be pulled here, so the minio service (`MINIO_ROOT_PASSWORD_FILE`, `mc ready local` healthcheck, user 10001 on the chowned objdata volume, the pinned tag `RELEASE.2025-09-07T16-13-09Z`) has never started.
- Full stack: the real gantry-web, api, worker, edge and github images were not available. The worker and github services, the ingress `depends_on` chain with real api and web, and the worker's own HEALTHCHECK (it has no HTTP port; compose relies on its Dockerfile) were not exercised.
- The default `KEYCLOAK_IMAGE` is `quay.io/keycloak/keycloak:26.4`, which is blocked here. I verified through the mirror image above, assuming it is the same Keycloak 26.4.x, and did not pull the quay one.
- `docker compose up --build` of the whole stack was not run. Only `gantry-launcher:dev` and `gantry-runner:dev` were built here by me.
- The runner Dockerfile's `RUNNER_TOOLCHAIN=full` path (apt installing git, build-essential, python3, jq) could not run because the sandbox cannot resolve Debian mirrors. Only the `minimal` variant was built and run, so a built image here has no git and no build tools, and git hooks, `GIT_CONFIG_*` behaviour with a real repo, and build stations are unexercised.
- Claude harness path: the adapter has never run against a real model (no key). The CLI flags (`--setting-sources user`, `--strict-mcp-config`, `--mcp-config`, `--disable-slash-commands`, `--append-system-prompt`, `--allowedTools`, `--max-turns`, `--output-format stream-json`), the env `CLAUDE_CODE_DISABLE_CLAUDE_MDS` and `CLAUDE_CONFIG_DIR`, the stream-json event shapes and the claim that repo-local settings, hooks and MCP config do not load are all unconfirmed. The auto-mode classifier denied running the downloaded native Claude binary here, so I did not run `claude --help` or `--version` and pinned `@anthropic-ai/claude-code@2.1.311` from the npm dist-tags without running it (it is installed in the runner image but never executed). Spike T9 is outstanding.
- Isolation tests T5 to T9, T11 and T12 are not covered. T7 and T8 depend on the edge. Smoke checks T1, T2, T3, T4 and T10 from a runner-like container I create with the launcher's flags, not from a launcher-created runner (except the launcher end-to-end run checking flags and teardown).
- Keycloak step-up: `auth_time` and `acr` (value `1`) are issued, but there is no second factor and no `amr`. The API must use `prompt=login` or `max_age` plus `auth_time` for step-up.
- Launcher unit tests do not cover the 'cancellation during final cleanup' or 'mixed child outcome' lifecycle cases beyond the integration tests listed (stop is idempotent and `teardown_incomplete` is retryable, but there is no fault-injection test). No test covers two concurrent starts racing for the last subnet slot across processes.
- Docker Hub 429s and quay.io/ghcr.io blocks in this sandbox mean a clean pull of every image has not been demonstrated.
